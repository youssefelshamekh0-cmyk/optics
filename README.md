# نظرة | نظام إدارة فروع البصريات

MVP عربي RTL لإدارة الفروع وحسابات فريق البيع، مبني على Next.js وSupabase Auth/Postgres. الأدوار في النسخة الحالية: مالك البراند وبائع، ولا يوجد تسجيل عام أو دور مدير فرع.

## ما الذي يمكن تجربته الآن؟

- دخول آمن عبر Supabase Auth.
- إنشاء الفروع وتعديلها وإيقافها، مع قصر البائع على الفروع والصلاحيات الممنوحة له.
- إنشاء حسابات بائعين، تعيين فروعهم وصلاحياتهم، وتغيير حالة الحساب أو كلمة مروره.
- فحص صلاحيات الخادم في كل طلب، وسجل تدقيق للعمليات الأساسية.
- لا يمنح التطبيق مفاتيح المتصفح صلاحية قراءة الجداول؛ العمليات تمر بخادم التطبيق.

البيع والعملاء والمخزون والعدسات والطلبات والمشتريات والحسابات والتقارير لم تدخل بعد في الـMVP.

## مراحل التنفيذ

1. **MVP الأساس الإداري (المنفذ محليًا):** دخول المالك، إعداد الفروع، إدارة البائعين والصلاحيات، سجل التدقيق.
2. **العملاء والوصفات:** ملفات العملاء، الوصفات الطبية، البحث وموافقات الخصوصية.
3. **البيع والتحصيل والتسليم:** عروض الأسعار، الفواتير، الدفعات، حالة تجهيز وتسليم النظارة.
4. **المنتجات والمخزون:** إطارات وعدسات، أرصدة كل فرع، جرد وتحويلات بين الفروع وتنبيهات الحد الأدنى.
5. **المشتريات والحسابات:** الموردون، أوامر الشراء، المصروفات، الصندوق والتسويات.
6. **التقارير والتشغيل:** تقارير المبيعات والربحية والمخزون، سجل تدقيق أوسع، النسخ الاحتياطي ومراجعة الأمان قبل الإنتاج.

## المتطلبات

- Node.js 20 أو أحدث.
- مشروع Supabase سحابي. لم يُربط المشروع بحساب Supabase في هذه البيئة بعد، ولذلك يلزم تزويد إعداداته قبل تشغيل دخول حقيقي.

## التشغيل

1. أنشئ مشروع Supabase، وخذ Project URL وPublishable key وService role key من إعدادات المشروع.
2. انسخ `.env.example` إلى `.env.local` واملأ القيم. احتفظ بـ`SUPABASE_SERVICE_ROLE_KEY` على الخادم فقط.
3. من Supabase افتح **Authentication → Sign In / Providers → Phone** وفعّل دخول الهاتف بكلمة مرور. لا يلزم مزود SMS إذا كانت أرقام الحسابات مؤكدة من المالك.
4. شغّل التطبيق. قاعدة البيانات في مشروع Supabase المرتبط تم تجهيزها بالفعل؛ لا تشغّل `supabase db push` قبل مزامنة سجل الترحيلات، لأن التأسيس الأول تم يدويًا من SQL Editor:

   ```powershell
   npm install
   ```

5. أضف `SUPABASE_SERVICE_ROLE_KEY` إلى `.env.local` محليًا. من PowerShell أنشئ حساب المالك. كلمة المرور الافتراضية هي رقم الهاتف بعد حذف الصفر الأول؛ يمكنك تعيين `OWNER_PASSWORD` محليًا إذا أردت كلمة مختلفة:

   ```powershell
   $env:OWNER_PHONE = Read-Host 'رقم الموبايل المصري'
   $env:OWNER_EMAIL = 'owner@example.com'
   $env:OWNER_NAME = 'مالك البراند'
   npm run db:owner
   Remove-Item Env:OWNER_PHONE
   ```

6. ابدأ التطبيق:

   ```powershell
   npm run dev
   ```

   ثم افتح `http://localhost:3000`.

للتجربة المحلية باستخدام Supabase CLI، تحتاج Docker Desktop؛ شغّل `npx supabase start` بدل ربط مشروع سحابي، واستخدم المفاتيح التي يعرضها CLI.

## الفحوصات

- `npm run build` يبني التطبيق.
- `npx supabase db advisors --help` يعرض خيارات مراجعة قاعدة البيانات.
- لا تُسجّل أسرار Supabase في Git أو في متغير يبدأ بـ`NEXT_PUBLIC_` باستثناء publishable key.
